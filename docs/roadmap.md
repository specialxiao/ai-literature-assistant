# 2–4 周实施计划

## 项目成功标准

最终演示必须在五分钟内完成：导入资料、提出中英文问题、看到相关原文和页码、得到有来源的回答、展示一份可复现评测结果。

## 第 1 周：可检索资料库

- Day 1：确定 3–5 篇允许公开使用的目标论文，写 10 条真实问题。
- Day 2：完成 PDF / Markdown / TXT 解析；预览每页抽取文本。
- Day 3：实现不跨页的滑窗切分，保留文档名和页码。
- Day 4：SQLite 建库、内容哈希去重、BM25 与字符 n-gram TF-IDF。
- Day 5：Streamlit 串起上传、论文列表、查询和证据展示。

验收：同一文件重复上传不重复；中英文查询都能返回正确页；扫描件和加密文件有明确错误。

## 第 2 周：基于证据回答

- Day 6：接入可替换的模型接口，明确“只根据证据回答”。
- Day 7：实现 `[S1]` 来源标记校验和无证据拒答。
- Day 8：实现兼容 API 的 embedding 后端和按端点隔离的本地缓存。
- Day 9：完善错误信息、加载状态、空库状态和演示样例。
- Day 10：录制一次完整演示，修复所有会卡住演示的问题。

验收：无 API Key 时仍可检索；有 Key 时回答只引用本轮来源；资料中的提示词不会变成系统指令。

## 第 3 周：评测与求职包装

- 将评测集扩充到 20–30 题，至少 5 题不可回答，并标注相关文档与页码。
- 比较 TF-IDF、BM25、embedding 与自动级联的 Recall@5、MRR、平均/P95 延迟及 embedding 调用率。
- 人工检查回答正确性、引用支持率、正确拒答率。
- 为 3 个失败案例分类：解析失败、检索失败、生成失败。
- 补齐单元测试、README 结果表和 2–3 分钟演示视频。

建议目标：Recall@5 ≥ 0.80、引用支持率 ≥ 90%、不可回答问题正确拒答率 ≥ 80%。这些是项目目标，不是当前样例数据的既成结果。

## 第 4 周：只做有证据的增强

按评测瓶颈选择一项：

- 检索召回差：调整自动级联阈值或 RRF 候选数量。
- 同名术语多：增加文档过滤器和查询改写。
- 表格/公式抽取差：评估版面解析器，不要立刻做 OCR 全家桶。
- 延迟高：批量 embedding、缓存查询、减少候选 chunk。

## 明确不做

在核心指标和演示稳定前，不增加联网论文搜索、自动引用格式、知识图谱、多 Agent、用户系统、复杂权限、移动端或全量 OCR。
