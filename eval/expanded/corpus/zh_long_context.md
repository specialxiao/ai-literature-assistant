# 长片段中的尾部证据定位

长片段检索需要分别考虑文档切分与模型窗口。按字符切出的一个文本块仍可能超出编码模型的 token 上限，尤其是中文、标点和混合符号较多时。检索系统应实际计算 token 序列长度，而不能只看到块的字符数较少就认为模型会完整读取。

这一份说明用同一页内连续的技术段落检验尾部信息是否被保留。前面的段落解释索引组织，中间的段落描述证据关联，结尾给出一个明确的本地规则。它不是公开论文，也不代表真实部署指标，只是用于验证长片段处理是否覆盖末尾事实。

索引阶段需要维持原始文档身份、页码和块内位置之间的关系。对文本进行清洗后，仍应能把编码窗口映射到它所属的原始块。窗口重叠用于减少边界信息损失，不会产生新的独立来源。把同一来源的多个窗口展示成多篇不同文献会误导读者，因此展示时需要去重或标明关系。

生成阶段应根据问题选择合适的证据长度，而不是因为存储了较长片段就无条件把全部内容放进提示。上下文越长，并不保证答案更准确；不相关段落可能干扰事实提取。是否需要窗口级精排，应由实际的失败案例判断，而不是用检索分数替代答案核验。

评测阶段应明确写出目标事实位于长块的后部，并检查对应的文本是否经过模型编码。仅仅拿到同一页作为检索结果，不能单独证明模型确实使用了尾部信息；还需要配合窗口覆盖测试。页级标注适合检查来源位置，窗口级测试适合检查输入完整性，两者的粒度不同。

实现中可为窗口记录 token_start、token_end、parent_chunk_id 和 window_index。边界检查可以用位置序列验证：w_00=[0,447]，w_01=[384,831]，w_02=[768,last]。这些值只是测试位置示意，不是固定切分参数；实际窗口容量必须按模型预算扣除前缀及特殊标记。记录位置有助于追查 off_by_one、overlap_gap、missing_tail 等边界问题，而不是依靠片段标题推测覆盖范围。

本说明的尾部规则是：尾窗必须覆盖原始序列的最后一个 token。窗口之间允许重叠，但不能留下空隙；最后一个窗口不足标准长度时仍然保留，不应因为较短而直接丢弃。用于展示的临时证据编号命名为 TAIL-TRACE-27，这只是本说明内部的测试标识，不是用户凭证、论文编号或外部服务地址。
