# 模型调用的失败分类

模型调用失败需要区分网络连接、认证、接口兼容与限流等类别。API Key 无效时应检查凭证和服务地址是否匹配，而不是无限重试。模型名或接口不存在时应核对模型配置及 API 路径，不能通过增加 token 预算修复。

限流或短暂服务故障可以考虑有上限的重试与退避，但应避免所有请求同时立即重试而放大压力。连接超时则需要检查网络、代理和完整的服务地址。向量服务与回答服务可以使用不同供应商，排障时应分别定位，不要把回答接口成功当作向量接口必然存在。

自动检索的容错边界应包围语义调用。语义后端不可用时返回已有 BM25 证据，界面说明发生降级。强制语义模式应明确显示失败，不要把故障伪装成资料中没有相关内容。日志与报错不应输出完整凭证。
