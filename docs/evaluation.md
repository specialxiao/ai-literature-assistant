# 评测方案

## 1. 检索评测

用 3–5 篇与你目标岗位相关的公开论文，人工写 20–30 个问题。每题标注一个或多个 `(filename, page)`，并保留至少 5 个资料中无法回答的问题。

主要指标：

- Recall@5：标注证据页是否至少有一个进入前 5。
- MRR：第一个正确证据的排名倒数。
- 无答案无命中率：不可回答问题没有任何结果越过检索阈值的比例。
- 平均/P95 检索延迟。
- Embedding 调用率：自动模式中实际触发语义检索的问题比例。
- 向量 API 查询比例：仅 API 后端计入，本地 E5 为零；不等于 HTTP 请求次数。

评测默认使用独立的 `data/evaluation.db`，不会清空应用资料库。分别测试 `--mode bm25`、`--mode local`、`--mode auto`；记录自动模式的 `TECHLIT_EMBEDDING_PROVIDER`。延迟需区分模型冷加载、首次建索引和同进程热查询，下载时间另计。

中英文评测至少包含中文问中文、英文问英文、中文问英文、英文问中文四组，并补充 512 tokens 以上文本块尾部的证据题。E5 默认只排序，不能把高余弦值当作证据充分；若提高 `TECHLIT_LOCAL_MIN_SCORE`，应在开发集调参、独立测试集报告误拒检和误命中。

不要只在内置合成样例上报成绩；它只用于冒烟测试。

## 2. 回答评测

每个问题由人工按 0/1 记录：

| 字段 | 通过标准 |
|---|---|
| `correct` | 核心结论与原文一致 |
| `complete` | 回答覆盖问题需要的关键点 |
| `citation_supported` | 每个实质性结论都能被所引来源支持 |
| `citation_valid` | 所有 `[S<n>]` 都来自本轮实际检索结果 |
| `proper_refusal` | 资料无答案时明确说证据不足 |

目标：引用有效率 100%（程序约束），引用支持率 ≥ 90%，不可回答题正确拒答率 ≥ 80%。LLM-as-judge 可作为辅助，但不能替代人工核对。
